# NodeWatch v1.0.0 — First Stable Release

NodeWatch is a native Python/Tkinter dashboard for a Raspberry Pi screen. It monitors **either the Pi itself or an authenticated remote Ubuntu/Linux server**—without Chromium or a browser.

**v1.0.0 is the first stable release**, following [v0.1.0 beta](https://github.com/harrydavies1/NodeWatch/releases/tag/v0.1.0). Server Mode has now been tested on a Dell OptiPlex running Ubuntu Server with a Raspberry Pi 3B and 3.5-inch OSOYOO SPI display.

## What's new since the v0.1.0 pre-release?

- **Ubuntu Server boots the metrics agent automatically (optional).** Run `bash deploy/server-agent-autostart.sh enable` on Ubuntu Server after configuring its token. The systemd service can be controlled with `status`, `logs`, and `disable`.
- **Samba NAS disk usage.** Keep Ubuntu's `/` system-disk metric while optionally monitoring a separate ext4 NAS filesystem with mount-error warnings.
- **Monitor both NAS drives independently.** Opt in to an extra **NAS Storage** page with separate usage bars, used/total/free capacity and missing-mount warnings for two disks (for example `/srv/nas/drive1` and `/srv/nas/drive2`).
- **Turn automatic page switching on or off.** Set `AUTO_ROTATE_PAGES=false` in the **Pi's** `.env` to keep the current page displayed. Touchscreen taps and Left/Right keys still switch pages, and statistics still refresh. `true` retains the default automatic rotation; `ROTATE_SECONDS` selects its interval.
- **More reliable setup and testing.** Documentation clarifies which commands run on Ubuntu versus the Pi, and tests now cover agent HTTP authentication, systemd service generation, two-drive metrics, dashboard page selection and config parsing. **35 tests passed** for the release candidate.

The original beta features remain: **Pi Mode**, authenticated **Server Mode**, native Tkinter fullscreen display, Pi health/network information, configurable polling and optional Pi desktop autostart.

## Upgrade an existing installation

You do **not** need to reinstall, reformat a drive or replace your local `.env`.

On **Ubuntu Server** (if you use Server Mode):

```bash
cd ~/pi-server-dashboard
git pull
sudo systemctl restart server-agent
```

On your **Raspberry Pi**:

```bash
cd ~/pi-server-dashboard
git pull
sudo reboot
```

Your `.env` files are local and should remain unchanged. Keep the existing remote agent URL and token.

To enable the dual-drive NAS display, add the following **only to Ubuntu Server's `.env`**, with your own real mount paths:

```ini
NAS_STORAGE_PATHS='[{"name":"NAS Drive 1","path":"/srv/nas/drive1"},{"name":"NAS Drive 2","path":"/srv/nas/drive2"}]'
```

Restart `server-agent`. Then check that both NAS mounts report `ok`. See [the NAS drive setup guide](https://github.com/harrydavies1/NodeWatch/blob/v1.0.0/docs/NAS_STORAGE.md).

To disable automatic screen switching, set the following in the **Pi's `.env`** and restart its dashboard:

```ini
AUTO_ROTATE_PAGES=false
```

To keep it on but switch every eight seconds, use `AUTO_ROTATE_PAGES=true` and `ROTATE_SECONDS=8`.

## Requirements and scope

- Raspberry Pi with a **working graphical desktop** and Tkinter; a compatible/configured screen driver is still needed for SPI displays.
- Python dependencies from `requirements.txt`; Ubuntu remote monitoring requires the read-only agent and matching private-network token.
- The HTTP agent is intended for a **trusted LAN or VPN**; do not expose port 8766 to the internet without additional protection.
- Samba/NAS stats show filesystem space, **not** Samba transfer rates, login activity, filesystem integrity or SMART disk health.
- This release provides a **source archive and Python code**, not a packaged executable or Windows installer.
