# NodeWatch v1.1.0 — HDD Temperature Monitoring

**Released:** 18 October 2026 · **Previous stable version:** [v1.0.0](https://github.com/harrydavies1/NodeWatch/releases/tag/v1.0.0)

NodeWatch is a lightweight **native Python/Tkinter Raspberry Pi dashboard** for local Pi stats and remote Ubuntu/Linux server monitoring—without a browser. This release adds **live HDD SMART temperatures**, an optional new touchscreen page and clearer setup diagnostics based on troubleshooting during the Dell OptiPlex / Raspberry Pi deployment.

## What's new since v1.0.0?

- **HDD temperatures:** monitor up to two physical HDDs via SMART (`smartctl`) on the Ubuntu Server, using an opt-in `HDD_TEMP_DRIVES` setting. The authenticated agent relays the readings to your Raspberry Pi.
- **Fourth display page:** **System Overview → Network & Services → NAS Storage → HDD Temperatures** when both NAS-storage and HDD-temperature monitoring are configured. Without the optional NAS page, HDD Temperatures becomes **page 3**. Pi Mode remains two pages.
- **Easy-to-read states:** temperature values in °C, advisory **NORMAL** (below 45°C), **WARM** (45–49.9°C) and **HOT** (50°C+), plus clear warnings for a sleeping, unsupported, absent or inaccessible drive. These thresholds are **not manufacturer-rated temperature limits**.
- **Conservative monitoring:** read-only `smartctl` commands, 60-second caching, disk-standby detection and a limited `sudoers` example. The agent remains unprivileged, and the feature never adjusts fan speeds or changes NAS data.
- **Disk replacement friendly:** recommends stable `/dev/disk/by-id/` device names to avoid accidental swaps when a disk is removed or replaced.
- **Expanded tests and docs:** SMART reading/attribute parsing, disabled mode, unsafe config input, missing/sleeping drives, cache interval and 2/3/4-page state selection.

The existing **optional page rotation** (including `AUTO_ROTATE_PAGES=false`), touch/keyboard page controls, NAS storage, authenticated Server Mode and Pi Mode are unchanged.

## Real-world setup issue we troubleshot

**Symptom:** After installing the updated NodeWatch code on the **Raspberry Pi**, the user still saw only **three pages**, with no fourth HDD-temperature page.

**Why this is possible:** the Pi creates the temperature page only after receiving a **non-empty `hdd_temperatures` list from the Ubuntu Server's agent**. Updating the display code on the Pi alone is insufficient. It was not confirmed exactly which installation step had been missed, so the checklist below covers the complete path.

**Diagnosis on the Raspberry Pi:**

```bash
cd ~/pi-server-dashboard
.venv/bin/python -c 'from dashboard import collect_state; s=collect_state(); print("Connected:",s["server"]["connected"]); print("HDD temperatures:",(s["server"]["stats"] or {}).get("hdd_temperatures"))'
```

Interpret the result:

| Output | Meaning |
| --- | --- |
| `Connected: False` | Pi cannot reach/authenticate to the server agent |
| `HDD temperatures: None` | No HDD temperature data field received (often an older agent; can also mean disconnected) |
| `HDD temperatures: []` | New agent is responding, but no HDDs are configured |
| `HDD temperatures: [{...}, {...}]` | Two configured drives are arriving; the temperature page should be available after updating/restarting the Pi display |

**Resolved setup path:** Update NodeWatch code **on both Ubuntu and the Pi**; set `HDD_TEMP_DRIVES` in **Ubuntu Server's** `.env`, not the Pi's; test the agent locally; restart `server-agent`; verify the Pi receives entries; and restart the Pi's Tkinter dashboard. The user subsequently confirmed: **“okay it works”**.

If SMART access fails, the page still appears when devices are configured, but shows `UNAVAILABLE` instead of inventing temperatures. This is a *different* issue from the missing fourth page.

For a full command-by-command troubleshooting guide, see [HDD Temperatures: only three pages](https://github.com/harrydavies1/NodeWatch/blob/v1.1.0/docs/HDD_TEMPERATURES.md#troubleshooting-case-updated-the-pi-but-still-only-see-three-pages).

## Upgrade from v1.0.0

**On Ubuntu Server**, keep your existing `.env` and agent token. Update the code and install the optional SMART dependency:

```bash
cd ~/pi-server-dashboard
git pull --ff-only
sudo apt install -y smartmontools
```

If enabling HDD monitoring, edit Ubuntu's `.env` and add one line using your verified device paths:

```ini
HDD_TEMP_DRIVES='[{"name":"NAS Drive 1","device":"/dev/sdb"},{"name":"NAS Drive 2","device":"/dev/sdc"}]'
```

**Check the actual drives before using those example paths** (`lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS`). Physical drive names can change after reboot. The agent normally needs a strictly limited `sudoers` rule to read SMART data without prompting; do not run the agent as root. Follow the [safe installation guide](https://github.com/harrydavies1/NodeWatch/blob/v1.1.0/docs/HDD_TEMPERATURES.md#step-3--grant-only-read-only-smart-access) before testing the readings.

On **Ubuntu Server**:

```bash
.venv/bin/python -c 'from dotenv import load_dotenv; load_dotenv(".env"); from metrics import snapshot; print(snapshot()["hdd_temperatures"])'
sudo systemctl restart server-agent
```

**On the Raspberry Pi**:

```bash
cd ~/pi-server-dashboard
git pull --ff-only
.venv/bin/python -c 'from dashboard import collect_state; s=collect_state(); print("Connected:",s["server"]["connected"]); print("HDDs:",(s["server"]["stats"] or {}).get("hdd_temperatures"))'
```

Restart the Tkinter dashboard, or run `sudo reboot` on the **Pi** if it starts automatically at desktop login.

**No reinstall is required**. Existing configurations, storage and shares remain intact. HDD temperature monitoring is optional and disabled until configured on Ubuntu. To make the temperature page appear as **page 4**, keep `NAS_STORAGE_PATHS` configured on Ubuntu for the NAS usage page as well.

## Tested scope and limitations

- The fourth page was **confirmed working by the user on their Raspberry Pi** after troubleshooting. CI covers the Python functionality, but every hardware/driver combination is not guaranteed.
- SMART results provide **temperature monitoring, not a health guarantee**. A prior Hitachi disk used during setup reported **52°C** and some reallocated sectors; `SMART PASSED` alone does not ensure reliability. Consider improved cooling, replacement and independent backups where appropriate.
- Device names may change when swapping drives; update `HDD_TEMP_DRIVES` and the matching sudoers entries together. Missing drives show unavailable readings.
- The read-only server agent is intended for a **trusted LAN/VPN**, protected by its token. Do not expose port 8766 to the public internet.
- GitHub supplies the Python source / release archive; this is not a compiled installer.
