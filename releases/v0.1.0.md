# NodeWatch v0.1.0 — Tkinter Pi Edition

**First beta release of NodeWatch**, a two-page Linux monitoring dashboard designed for a Raspberry Pi with a small SPI screen. It runs as a native Python/Tkinter application — **no browser or Chromium required**.

## Highlights

- **Pi Mode** — show live CPU usage, RAM, root filesystem, temperature where available, uptime and networking from the Raspberry Pi itself. No separate server needed.
- **Server Mode** — read remote Ubuntu/Linux server stats via a small authenticated `agent.py`; keep local Pi health on the second page.
- **Two fullscreen pages** — system overview and network/services, with configurable refresh and automatic rotation.
- **Touch and keyboard navigation** — tap the left or right of the screen, or use arrow keys.
- **Optional startup at graphical desktop login** — `bash python-display/autostart.sh enable`; `disable` and `status` commands included. Autostart is not enabled by default.
- **Docs and tests** — separate Pi Mode, Server Mode and autostart instructions, troubleshooting and Python test coverage.

## Hardware used and testing status

- **Raspberry Pi:** Raspberry Pi 3 Model B (Pi 3B)
- **Screen:** 3.5-inch OSOYOO SPI RPi Display V1.0
- **Server hardware:** Basic Dell OptiPlex running Ubuntu Server

The Tkinter dashboard was confirmed working in **Pi Mode** on the Pi 3B and OSOYOO SPI display: fullscreen rendering, live local stats, alternating pages and automatic launch after graphical desktop login. Automated Python tests pass. **The complete Ubuntu Server agent-to-Pi connection has not yet been validated end to end on the physical OptiPlex**, so this release is marked as a **pre-release**.

## Installation

On Raspberry Pi OS with an already-working graphical desktop/display:

```bash
sudo apt update
sudo apt install -y git python3 python3-tk python3-venv python3-pip
git clone git@github.com:harrydavies1/pi-server-dashboard.git
cd pi-server-dashboard
git checkout v0.1.0
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r requirements.txt
cp -n .env.example .env
```

The repository is private: cloning requires GitHub access. If you've already installed NodeWatch, **keep your existing `.env` and `.venv`**; do not clone a second copy.

**Pi Mode:** leave `REMOTE_AGENT_URL=` empty in the Pi's `.env`.

**Server Mode:** run the agent on Ubuntu Server, then set `REMOTE_AGENT_URL=http://YOUR_SERVER_IP:8766` and a matching `REMOTE_AGENT_TOKEN` in the Pi's `.env`.

To start the display from the Pi's graphical desktop:

```bash
bash python-display/start-native.sh
```

For an optional automatic launch after desktop login:

```bash
bash python-display/autostart.sh enable
```

For detailed instructions, see [README](https://github.com/harrydavies1/pi-server-dashboard/blob/v0.1.0/README.md), [Pi Mode](https://github.com/harrydavies1/pi-server-dashboard/blob/v0.1.0/docs/PI_MODE.md), [Server Mode](https://github.com/harrydavies1/pi-server-dashboard/blob/v0.1.0/docs/SERVER_MODE.md) and [Optional Autostart](https://github.com/harrydavies1/pi-server-dashboard/blob/v0.1.0/docs/AUTOSTART.md).

## Notes

- The native Tkinter display **requires a working graphical desktop** and a correctly driven SPI display; it is not a direct framebuffer program.
- Temperature data depends on sensors exposed by the OS.
- Network byte counters are cumulative since boot rather than instantaneous bandwidth.
- The server agent should be reachable only over a trusted LAN or VPN. Remote connection errors are shown as offline; they are not silently replaced with Pi stats.
